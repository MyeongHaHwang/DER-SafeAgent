# IJCIP Reproducibility Guide

This guide reproduces every experiment that ships with the IJCIP
revision of DER-SecAgent. All commands are run from the repository root
(`2026_DER-SecAgent/`).

## 1. Environment

- Python 3.11+
- `pip install -r requirements.txt`
- Optional GPU stack (only required for real LoRA latency rows):
  `pip install -r code/finetuning/requirements.txt`
- Tested on: Linux 6.17.0 / Bash, CUDA optional.

## 2. Dataset paths

| Dataset           | Required path                                           | Status |
|-------------------|---------------------------------------------------------|---|
| UNSW-MG24 mock    | `code/datasets/unsw_mg24/raw/alerts_mock.csv`           | auto-generated by `make ijcip-experiments` if missing |
| UNSW-MG24 real    | `code/datasets/unsw_mg24/raw/alerts.csv`                | optional; ship the dataset CSV manually |
| SWaT / WADI / TON_IoT / EPIC | `code/datasets/<name>/raw/<name>.csv`        | optional; not bundled |

The benchmark adapter checks for the real CSV first, falls back to the
mock, and otherwise records `status=not_run` with a reason.

## 3. Real-LoRA backbones (latency rows)

| Backbone                    | Env var to point at adapter           |
|-----------------------------|----------------------------------------|
| Qwen2.5-7B-Instruct LoRA    | `DER_LORA_ADAPTER_QWEN7B`              |
| Llama-3.1-8B-Instruct LoRA  | `DER_LORA_ADAPTER_LLAMA8B`             |

If the env var is unset or the path does not exist, the latency table
records the row as `not_run` with the reason printed in
`code/results/ijcip_latency/README.md`.

## 4. One-shot reproduction

```bash
make ijcip-test           # 35 unit tests, expected to pass
make ijcip-experiments    # runs every IJCIP experiment; ~3 min on CPU
make ijcip-figures        # re-renders figures only
```

`ijcip-experiments` is graceful: a failing sub-command logs a warning and
the rest continue.

## 5. Per-experiment commands

```bash
# T2 external benchmarks (UNSW-MG24 mock + not-run rows for the rest)
python3 -m code.evaluation.benchmark_external.run_external_benchmarks \
    --max-samples 200

# T3 adversarial robustness (six perturbation families × four detectors)
python3 -m code.evaluation.adversarial_safety.run_robustness \
    --detectors der_secagent,single_llm,prior_mas,rule_ids \
    --n-per-family 10 --seed 0

# T4 stronger baselines (rule_ids + 3 LLM + 5 IJCIP additions + oracle)
python3 -m code.evaluation.run_ijcip_baselines --seeds 0,1,2

# T5 ablation matrix
python3 -m code.evaluation.run_ijcip_ablation --seeds 0,1,2

# T6 HITL sensitivity (5 operators × 6 SLOs × 3 scenarios)
python3 -m code.evaluation.hitl_sensitivity.run_hitl_sensitivity \
    --seeds 0,1 --slos 5,30,60,120

# T7 objective sensitivity / Pareto
python3 -m code.evaluation.objective_sensitivity.run_objective_sensitivity \
    --seeds 0 --ens-weights 1,5,20 --tier-penalties 0,1.5,5 \
    --confidence-thresholds 0.3,0.5,0.7

# T8 LLM latency (heuristic + optional real LoRA via env vars)
python3 -m code.evaluation.latency.run_llm_latency --n-calls 200

# T9 figures + LaTeX tables
python3 -m code.evaluation.build_ijcip_figures
```

## 7. Limitations / not-run items

The IJCIP revision *does not fabricate* numbers. The following cells are
logged as `not_run` with a documented reason:

- SWaT, WADI, TON_IoT, EPIC: no labelled CSV in repo. Drop a CSV under
  `code/datasets/<dataset>/raw/<dataset>.csv` to enable.
- Qwen2.5-7B / Llama-3.1-8B real-LoRA latency: requires
  `DER_LORA_ADAPTER_QWEN7B` / `DER_LORA_ADAPTER_LLAMA8B` env vars.
- The bundled v0.1 fine-tuning corpus (200 examples) is for pipeline
  validation only; downstream LoRA training requires the v1.0 corpus
  (planned, not yet bundled).
